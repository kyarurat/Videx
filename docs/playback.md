# 音视频播放

视频和音频共用 `src/media/MpvPlayer`。Qt Widgets 负责操作与布局，mpv 负责解码、时间轴和音频输出；`VideoView` 使用 Qt OpenGL 画布和 libmpv render API 显示视频，避免依赖 Windows / X11 原生窗口句柄。新增 Qt OpenGLWidgets 模块用于这一原生画布。

等待视频画布创建超过 5 秒时停止当前会话并提示检查显卡驱动和 OpenGL 支持。新建引擎、复用音频引擎后打开视频、以及音频入口发现实际视频的升级路径均受此保护；切换文件和创建成功会取消旧等待。

## 操作

双击文件或按 Enter 打开；文件树上下键连续浏览时，焦点保留在文件树。音频显示媒体名称及文件中已有的艺术家、专辑信息，无视频流也可以加载。封面不当作视频，不额外展示封面。

成功加载后显示播放／暂停、进度、当前时间／总时长、倍速、静音、音量和全屏。不可跳转或总时长未知时禁用进度条。时间更新不会反过来触发跳转；拖动在释放时跳转，键盘和点击操作也能调整进度。播放完后保留最后画面或音频信息，再次播放从头开始。

| 快捷键 | 查看区聚焦时的操作 |
| --- | --- |
| Space | 播放／暂停；长按不反复切换 |
| ← / → | 短按后退／前进 5 秒；长按 ← 每次后退 1 秒，长按 → 临时 2× 播放，松开恢复原倍速 |
| ↑ / ↓ | 音量增减 5；长按重复操作 |
| M | 静音；长按不反复切换 |
| PageUp / PageDown | 上一项／下一项，与图片切换习惯一致 |
| F / Esc | 全屏／退出全屏，沿用已有查看器行为 |

点击查看区后可使用播放快捷键；音视频已加载且可跳转时，文件树选中文件也可使用左右键。选中目录时保留左右键展开／折叠，文件树上下键和控件自身的键盘操作保持不变。短按左右键均在松开时跳转 5 秒；右键按住约 300 毫秒后临时使用 2×，松开或焦点移走恢复原倍速，暂停状态保持不变。左键按住约 300 毫秒后开始后退，每次 1 秒，随后随系统按键重复继续后退，松开不追加 5 秒跳转。跳转使用精确模式，避免被视频关键帧间隔放大。工具栏也提供上一项／下一项。

导航沿用文件树排序，每批最多检查 128 行并返回事件循环，找到下一项即停止，不先构建目录剩余全部候选列表。音视频按需检查实际媒体流，纯音频 MP4 属于音频，视频导航会跳过它。已播放或已检查的类型按路径、大小和修改时间缓存（最多 1024 个）；文件变化后重新检查。检查使用独立、暂停且无音频输出的 mpv 引擎，浏览目录时不预先探测；手动打开其他文件或目录会取消未完成的导航。单个候选检查超过 10 秒时提示直接打开重试。无法解码的候选显示错误和文件信息，不自动跳过。切换均保留本次应用会话中的静音选择。

“设置 → 播放”可配置默认倍速与自动下一项。自动下一项只响应自然结束，手动切换、删除文件或加载失败不会触发；序列末尾停止，不循环。切换到图片、文件信息或其他目录会异步停止旧会话。引擎和视频渲染器复用，仅在最终销毁时释放；过期回复与旧播放事件不恢复旧画面或声音。已加载媒体直接替换，未完成加载先等待异步停止确认，避免误认旧文件的开始事件。

按音频扩展名打开时不等待或初始化视频画布；如果实际包含可播放视频，会在读取流信息后切换视频输出。实际纯音频 MP4 等歧义扩展名仍通过视频入口检查。引擎一次事件批次只更新一次界面，视频状态不重建音频信息。长按后退的相对跳转最多每 100 毫秒合并发送一次，保留累计秒数；绝对跳转和换文件会清除旧待发请求。mpv 保持精确跳转，长 GOP 视频仍可能需要从较远关键帧重新解码。

打开只向 mpv 传递路径并异步加载，文件总大小不会直接决定应用缓存大小。数十 GiB 音视频是否快速打开仍取决于容器索引、存储速度、编码及音频设备；本次未增加按文件总大小分配的缓存，也未减少流探测预算。

正常关闭时保存最后一次会话：根目录、文件树展开／选中／滚动位置、当前文件，以及音视频位置、时长、倍速、音量、静音和播放／暂停状态。启动恢复最后文件；已播放完或不可定位的媒体从头开始。上次文件或根目录丢失、不可读时进入空白页，不弹出错误。设置中可分别关闭目录恢复和文件／播放恢复。图片重新加载，缩放和平移不跨重启保存。当前只保存最后会话，不建立多文件历史库。

## 外部文件操作

当前文件及其父目录由独立监听器跟踪，变化通知合并约 150 毫秒后处理。Windows 使用卷与文件 ID，Linux 使用设备号与 inode 确认文件身份；同目录重命名更新名称、路径和文件树定位，保留进度与播放／暂停状态。仅大小写变化也会更新显示。原路径被其他文件替换、音视频内容被修改、文件被删除或移出当前目录后，关闭媒体并回到未打开页面，通过状态栏说明原因，不触发自动下一项。未知移动目标不递归搜索磁盘；同目录查找在后台进行，身份不可确认或匹配不唯一时安全退出。

Windows 在允许共享读写和删除的基础上，使用属性访问句柄申请 RH oplock 通知。普通共享读取不会停止播放；发生冲突的独占访问时，异步停止媒体，等待对应 `END_FILE` 确认实际卸载后再关闭通知句柄，让外部请求继续，并在状态栏提示。mpv 正常停止失败时尝试在后台销毁引擎；通知等待最多 2 秒，超时明确提示无法保证对方成功，不无限阻塞外部操作。旧文件的通知与释放结果不能清空新选择。

Windows 会对重命名和某些原子替换发出相同的句柄缓存通知；部分替换接口即使允许共享删除仍要求先关闭目标。对于可恢复进度的媒体，先保留画面与状态并短暂卸载，身份监听确认是同一文件改名后自动重新加载、定位并恢复原来的播放／暂停状态；确认是替换或移出则关闭。不可定位媒体保留共享读取，普通改名可跟随，但不能保证兼容所有原子替换接口。

文件系统不提供通知（包括 Linux 的普通文件读取和部分网络共享、外接盘）时，可定位媒体暂停 5 秒后异步释放文件。界面保留时间轴、音频信息或一帧最大 3840 × 2160 的视频画面；继续播放时暂停加载、精确定位，再恢复声音。释放后跳转会重新打开为暂停状态，定位后重新计算 5 秒。不可定位的媒体不自动释放，避免失去无法恢复的进度；状态栏说明这一限制。此恢复只用于当前会话，不读写播放历史。

原生通知只能让出 Videx 自己的读取，不能解除其他应用的占用；不保证不支持通知的文件系统或不等待通知确认的外部程序能够自动取得独占访问。目录整体移动或删除沿用关闭目录、要求重新选择的行为。

## 构建和分发

Qt 6.5+ 需含 OpenGLWidgets，另需 libmpv 开发库。Ubuntu 安装 `libmpv-dev` 后由 CMake 查找系统库。Windows SDK 应含 `include/mpv/client.h`、导入库及 mpv DLL，通过 `-DMPV_ROOT=<SDK目录>` 配置，构建与安装会复制 mpv DLL。Qt OpenGLWidgets 运行库随 `windeployqt` 部署。

本次 Windows 开发 SDK：shinchiro/mpv-winbuild-cmake 的 `mpv-dev-x86_64-20260928-git-e470f8986e.7z`，使用通用 x86_64 构建。源码不保存本机 SDK 绝对路径，也不会在应用启动时下载依赖。分发使用的 mpv、FFmpeg 和编解码库版本决定实际支持范围；应同时提供该构建对应的第三方许可与源码材料，见 [第三方依赖](third-party.md)。

## 验证范围

`playback_checks` 生成 WAV 样本，覆盖音频加载、暂停、跳转、音量、静音、倍速、键盘滑块操作、重播、自动下一项、末尾停止、快速切换及损坏文件恢复。回归检查还覆盖切换前静音请求尚未回填的情况、实际媒体类型导航、暂停静音的导航检查及取消过期导航。

`file_operations_checks` 由独立进程对临时媒体执行重命名（含仅大小写变化）、删除、移动、修改、原子替换和独占打开，验证播放／暂停状态跟随、2 秒内独占让出、暂停释放后的定位恢复、图片更新、文件身份缓存和过期事件隔离。Windows 通过 `VIDEX_TEST_VIDEO` 指定测试视频并使用 `-platform windows`，另验证真实 OpenGL 画面冻结、恢复及活动视频让出；offscreen 不证明视频显示。大于 32 MiB 的图片输入快照也有独立读写与原文件删除检查。

设置 `VIDEX_TEST_VIDEO` 为生成的彩色测试图 H.264/AAC MP4 路径，并使用 `videx_playback_checks -platform windows` 验证实际 OpenGL 视频输出。程序读取视频 framebuffer，检查彩色像素，并保存视频帧与深浅主题截图到运行目录的 artifacts。

同时设置 `VIDEX_TEST_AUDIO_CONTAINER` 为纯音频 MP4 路径，可以验证纯音频 MP4 连续导航，以及视频自动下一项／上一项跳过纯音频 MP4。`playback_lifecycle_checks` 已纳入 CTest：该目标在 Release 下也为播放组件启用 Qt 断言，覆盖空闲、音频播放、长按加速时销毁完整 PlayerWidget，以及关闭主窗口。另运行 `videx_playback_lifecycle_checks -platform windows`（Linux 使用实际可用的原生平台），配合 `VIDEX_TEST_VIDEO` 验证活动视频与加速时销毁完整界面，以及先销毁画布、先销毁后端的两种顺序。offscreen 模式跳过原生 OpenGL 检查。

无界面检查使用 Qt offscreen 和 mpv null 视频输出，只证明音频／状态逻辑，不能证明图形显示。Windows 已取得实际视频 framebuffer 和主题截图；Ubuntu 的编译、X11 / Wayland 显示、实际扬声器听感、不同显卡和打包环境仍需各自补充验证，不宣称支持所有编码组合。
