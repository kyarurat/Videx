# Videx

轻量的原生本地媒体浏览与查看工具，使用 C++20、Qt 6 Widgets 和 CMake。
在左侧浏览本地文件，在右侧查看图片或通过 libmpv 播放视频和音频，音频文件作为独立媒体类型支持。

当前版本：`0.2.0-rc.2` · 作者：[KyaruRat](https://github.com/kyarurat) · [GitHub 仓库](https://github.com/kyarurat/Videx)

本次发布 Windows 11 x64 便携版。Linux 已完成构建和部分验证，原生视频仍有黑屏问题，详细结果见下方“平台验证情况”。

| 相机 RAW、HEIC/AVIF、拍摄信息 | 已实现，具体格式与编码范围见下方说明 |
| 视频播放 | 已接入 libmpv，提供基本播放控制和 Qt OpenGL 画布 |
| 音频播放 | 与视频共用后端，显示名称和可用的艺术家／专辑信息 |

## 下载与运行

[下载 0.2.0-rc.2 Windows 候选版本](https://github.com/kyarurat/Videx/releases/tag/0.2.0-rc.2) · [更新说明](docs/releases/0.2.0-rc.2.md)

Windows 11 x64 下载 `Videx-0.2.0-rc.2-windows-x64.zip`，完整解压后运行 `Videx.exe`。便携包已包含 Qt、libmpv 和图片解码运行库，无需安装开发环境；请保留同目录中的 DLL 和插件文件夹。发布页同时提供源码包及 `SHA256SUMS-0.2.0-rc.2.txt` 校验文件。

首次打开后点击“打开文件或文件夹”，选择本地目录，在文件树中双击媒体即可查看或播放。本版本界面为简体中文。此次 GitHub Release 仅提供 Windows 二进制包；Linux 打包工具和内部测试包不代表 Linux 已通过完整验收。

## 构建

需要 Qt 6.5 或更高版本（Core / Gui / Widgets / Svg / Concurrent / OpenGLWidgets）、libmpv 开发包、CMake 3.21+ 与 C++20 编译器。缺失的图片依赖默认从固定版本源码构建，首次配置需要网络；Windows 的 AVIF 解码库构建还需要 Perl，可使用 Git for Windows 自带版本。

Windows 配置时用 `-DMPV_ROOT=<SDK目录>` 指定含 `include/mpv/client.h`、导入库及 `libmpv-2.dll` 的 SDK。Ubuntu 安装 `libmpv-dev`。播放及验证说明见 [音视频播放](docs/playback.md)。

```sh
cmake -S . -B build -DCMAKE_PREFIX_PATH=<Qt安装目录>
cmake --build build --parallel
```

Windows 配置示例（使用与 Qt 匹配的编译器和生成器）：

```sh
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release -DCMAKE_PREFIX_PATH=<Qt安装目录> -DMPV_ROOT=<mpvSDK目录>
cmake --build build --config Release --parallel
```

发布时使用 Release 构建；单配置生成器在配置时加 `-DCMAKE_BUILD_TYPE=Release`，多配置生成器使用 `cmake --build build --config Release --parallel`。源码构建的 LibRaw 默认在所有构建类型中启用可用的 OpenMP 多核解码；缺少 OpenMP 时会在配置阶段提示。性能测量与限制见 [RAW 性能记录](docs/raw-performance.md)。

自行构建时，Windows 运行需让 Qt 与编译器运行库位于 PATH，或使用 Qt 的 `windeployqt` 部署。构建会把 libmpv、Exiv2、libheif、所需的 MinGW OpenMP DLL 和额外图片插件复制到可执行文件旁；`windeployqt` 负责 Qt 及相关运行库，第三方图片解码库也需随程序分发。手动复制可执行文件到另一目录时，应同时复制这些依赖。Ubuntu 构建所需的 Qt 和图片依赖版本由 CMake 检查，系统包不足时需使用符合要求的 Qt SDK 及源码依赖。

## 界面

- 首次启动显示未打开界面，点击“打开文件或文件夹”或按 Ctrl+O 打开统一选择器。选文件时，以文件所在文件夹为根目录并高亮该文件、显示文件信息；选文件夹时，以所选文件夹为根目录。
- 选择器统一使用“打开”按钮，自动判断文件或文件夹；选中任一项都会填入名称，名称留空则打开当前文件夹。双击文件夹进入浏览，双击文件直接打开，取消选择不改变当前内容。对话框只读，不提供新建文件夹或文件类型筛选，直接展示所有文件。
- 文件树显示目录内的所有文件和子文件夹（包含隐藏项），不按视频扩展名过滤。双击文件夹、按回车（含小键盘 Enter）或点击展开箭头切换展开／折叠，QFileSystemModel 按需加载，不递归扫描整个目录。
- 鼠标单击只改变文件树选中项；上下键选中文件时立即打开，选中目录时保留当前画面并通过 Enter 展开／收起；双击文件或按 Enter 也可在右侧查看图片或播放音视频，不支持的文件显示明确提示及基本信息。双击文件夹仅展开或折叠，不影响右侧内容；切换根目录会清空先前内容。同目录外部重命名会更新当前文件名称、路径和定位；删除或无法定位的移动会关闭失效媒体并提示。
- 图片工具栏提供上一张／下一张、适应窗口、原始尺寸、缩放和“详细信息”。查看区内 PageUp / PageDown 连续切图，Ctrl+滚轮或 `+` / `-` 缩放。原始尺寸按物理像素显示，跨屏时适配屏幕缩放比例。
- 图片在后台解码，先显示适合窗口的预览；点击“原始尺寸”或放大超过预览清晰度时加载原图，升级时保留缩放和平移。按需预加载相邻图片及符合预算的当前原图，缓存有容量限制。先显示图片，再异步读取 EXIF/IPTC/XMP。详细信息显示文件中保存的光圈、曝光、ISO、相机、镜头和地理坐标等，不推测缺失数据。快速切换不会显示旧文件的图片或拍摄信息。
- 文件树顶部提供“收起侧栏”按钮，隐藏整个左侧面板并将空间让给右侧。收起后，右侧顶部显示“展开文件树”按钮，可一键恢复；也支持“视图 → 资源管理器”或 Ctrl+B。通过这些入口修改的显隐状态会立即保存，重启继续使用。
- 播放控制栏属于右侧媒体区域，左侧文件树独占整列。浏览文件信息及图片时隐藏控制栏，仅在成功加载视频或音频后显示。
- 成功打开目录后用 QSettings 保存路径，默认下次启动自动恢复。上次目录不存在或不可读时回到未打开状态并显示提示，不阻塞重新选择。打开失败不会覆盖之前保存的有效路径。
- 已打开的根目录被外部删除或重命名时，清理浏览状态并提示重新选择。后台刷新当前文件信息时，不改变文件树中的选择位置。
- “文件 → 设置”中的选项在点击“应用”或“确定”后持久保存，重启恢复主题、面板显隐及各项偏好；取消放弃未应用修改，恢复默认后需应用才能保存。默认倍速与自动下一项已生效，播放进度恢复暂缓。
- 设置窗口打开时，未编辑的显隐选项随主窗口操作同步；已经明确编辑的选项保留为待应用草稿。
- 主题默认自动跟随系统，可手动选择深色或浅色；自动模式在系统不报告配色时使用浅色。窗口原生标题栏由系统管理。
- 关闭时保存窗口大小、位置和侧栏宽度，重启恢复；隐藏侧栏时保留其展开宽度，全屏退出程序后恢复进入全屏前的窗口状态。
- Ctrl+O 打开文件或文件夹，Ctrl+, 设置，Ctrl+B 文件树，F 全屏，Esc 退出全屏。文件树上下键用于浏览，左右键的音视频操作见下方说明；其他控件保留原生键盘操作。

## 音视频播放

视频和音频通过同一 libmpv 后端提供播放／暂停、进度跳转、音量、静音和播放速度。音频视图展示名称和已有的艺术家／专辑信息；无需包含视频流，封面不作为视频画面。重启后的播放历史恢复仍暂缓。

控件随当前媒体类型切换：图片使用查看工具，成功加载的视频或音频使用播放控制。导航默认限制在同一媒体类别，自然结束时可按设置播放下一项，序列末尾不循环。查看区内 Space 暂停、左右方向键短按跳转五秒、上下方向键调整音量、M 静音、PageUp / PageDown 切换同类文件。右方向键长按临时 2×、松开恢复原倍速，左方向键长按每次精确后退一秒。文件树选中文件时也支持左右方向键播放操作；选中目录时保留展开／折叠，上下键和其他控件保持原有导航。

## 外部文件操作

- 同目录重命名按文件身份确认，支持连续改名和仅大小写变化；保留播放进度、播放／暂停状态及图片视图。不会凭名称或大小猜测移动目标，也不递归搜索磁盘。
- 删除、移出当前目录、修改或替换音视频内容时，停止并释放文件，回到未打开媒体页，不自动播放下一项。图片修改或替换沿用后台自动刷新；快速换文件时丢弃旧图片、元数据及恢复请求。
- Windows 在共享读写和删除的基础上接收独占访问冲突通知，按需让出文件并通过状态栏提示，不自动重新打开。通知等待最多 2 秒；不支持通知的位置或不等待的外部程序不能保证自动取得独占访问。
- 不支持通知的位置，可定位音视频暂停 5 秒后释放读取，保留音频信息或一帧有界视频画面。继续播放时先加载和精确定位，再恢复声音；释放后跳转保持暂停。不可恢复进度的媒体继续共享读取，并说明限制。
- 图片源采用可取消的短时快照读取，随后关闭原文件再解码；大于 32 MiB 的输入使用自动清理的私有临时文件，仍遵守 512 MiB 文件限制。

暂停释放后的恢复仅驻留当前会话；重启应用后的播放历史恢复仍未实现。所在根目录被移动或删除时关闭目录，不扫描磁盘寻找文件。详细机制与边界见 [音视频播放](docs/playback.md#外部文件操作)。

## 平台验证情况

以下是截至 2026-10-16 的实际结果。常规回归使用 offscreen，不能单独证明原生视频画面正常。

| 环境 | 已完成 | 尚存问题或未验证项 |
| --- | --- | --- |
| Windows 11 x64，Qt 6.11.2 / MinGW 13.1 | Debug、Release 各 5 组回归通过；Release 原生文件操作、视频播放和窗口销毁检查通过 | 不代表所有媒体编码、网络共享或外部程序均兼容；独立干净 Windows 虚拟机仍未验证 |
| Ubuntu 24.04.4 / WSL 2，Qt 6.11.2 / libmpv 0.37.0 | Release 构建，文件操作、图片、界面及无界面销毁检查通过 | 完整播放检查偶发相对跳转偏差；WSLg 原生视频可黑屏；一次未保存调用栈的关闭崩溃未稳定复现 |
| Ubuntu 26.04.1 / Hyper-V 原生桌面，Qt 6.10.2 及测试包 Qt 6.11.2 / libmpv 0.41.0 | Release 构建和 5 组常规回归通过；原生文件操作及窗口销毁有通过记录，曾显示正常彩色视频 | X11 重复运行及 Wayland 均复现黑屏，时间轴仍前进；一次冻结画面异常网格未稳定复现，原生视频尚未稳定通过 |
| Ubuntu Desktop 24.04 x64 原生桌面 | 仍为目标平台 | 尚待补测，WSL 24.04 和 Hyper-V 26.04 均不能替代该项验证 |

Hyper-V 使用 Mesa llvmpipe 软件 OpenGL，尚未验证真实 GPU 和人工扬声器听感。已定位并修复“长按加速到片尾”时的递归崩溃，新增回归检查；这不代表 Linux 黑屏或此前未复现的关闭崩溃已修复。完整环境、命令与限制见 [Linux 测试记录](docs/wsl-testing.md)。

## 性能与当前边界

- 图片预览最大 3840 × 2160；图片缓存 256 MiB，元数据缓存 4 MiB；预计原图像素数据超过 128 MiB 时不自动预加载原图，仍可按需请求。文件保持 512 MiB / 100 MP 限制，多 GiB 图片尚不支持。
- 同目录打开复用文件树模型，同类导航每批最多检查 128 行，按需探测并缓存音视频类型；不递归扫描目录或启动时生成全部缩略图。十万文件目录首次自然排序仍可能短暂停顿。
- 音视频按需加载，切换时复用引擎，纯音频避免初始化视频画布。已用 20 GiB 稀疏样本验证大文件寻址、加载和跳转；这不代表所有压缩视频、长 GOP 或冷磁盘读取的速度。

本机测量结果、复现方法与验证限制见 [性能验证](docs/performance.md)，RAW 分阶段耗时见 [RAW 性能记录](docs/raw-performance.md)。

## 结构

- `src/app`：浏览控制器、文件信息与会话状态、主题管理器。
- `src/services`：设置保存、文件身份与选中文件监听，以及隔离的 Windows 外部访问通知；测试使用隔离的 INI 文件，不修改用户设置。
- `src/media`：媒体分类与同类导航、libmpv 播放封装、后台图片加载、Qt/LibRaw/libheif 解码及 Exiv2 元数据读取。
- `src/ui/images`：图片显示、缩放平移、图片工具栏与详细信息窗口。
- `src/ui`：主窗口协调器；explorer、player、dialogs 按功能拆分；common 存放真正复用的组件。
- `resources/styles/common.qss`：共享布局样式及语义颜色占位符，由 ThemeManager 使用深浅调色板填充。
- MainWindow 负责协调：文件或文件夹选择 → BrowserController 校验并记忆根目录 → ExplorerWidget 展示文件树；打开文件后交给右侧查看器后台解码。OpenPathDialog 基于 Qt 文件对话框，统一支持两种选择；浏览目录时不逐个探测图片或递归扫描。

## 验证

```sh
ctest --test-dir build --output-on-failure
```

默认构建轻量集成检查程序，使用隔离的真实临时文件验证首次启动、独立进程重启恢复、文件与文件夹选择及取消、多层文件树、图片和其他类型文件的打开、空目录和失效路径处理。截图保存在运行目录的 `artifacts/browser`；Windows 视觉检查可运行 `videx_ui_checks -platform windows`。可用 `-DBUILD_TESTING=OFF` 关闭检查程序构建。

另有 `videx_image_checks` 验证图片内容解码、改名 RAW DNG、EXIF/IPTC/XMP/GPS、格式不支持提示、预加载竞态、异步元数据、连续键盘切图和模拟屏幕缩放变化；源码构建 libheif 时验证真实 HEIC/AVIF 样本，系统库构建可通过 `VIDEX_HEIF_TEST_FILES_DIR` 指定样本目录。图片截图位于 `artifacts/images`。实际双屏拖动仍需补充验证。

`videx_playback_checks` 覆盖音视频类别、播放控制、快捷键、快速切换、损坏文件恢复、画布超时和长按加速到片尾；`videx_playback_lifecycle_checks` 在 Release 下启用 Qt 断言，检查播放组件销毁与 OpenGL 生命周期。`videx_file_operations_checks` 使用独立进程验证重命名、删除、移动、修改、替换、Windows 独占访问让出、暂停释放／恢复及过期结果隔离。共 5 组常规回归，原生视频样本与运行方式见 [音视频验证](docs/playback.md)，各平台结果见上方表格。

## 应用图标

`images/logo.png` 是窗口图标源文件，通过 Qt 资源嵌入，Windows 和 Linux 共用。
`images/logo.ico` 包含 16、20、24、32、40、48、64、128、256 像素版本，用于 Windows 可执行文件图标。
更换 PNG 后，在 Windows 运行 `powershell -ExecutionPolicy Bypass -File tools/GenerateIcon.ps1` 更新 ICO，然后重新构建。
生成脚本使用系统自带的图像处理能力，不增加应用运行或正常构建依赖。
